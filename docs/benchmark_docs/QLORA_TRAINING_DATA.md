## 2. Pre-train data split (80 / 10 / 10, stratified by lang)

Split is **stratified per language** (each lang gets its own 80/10/10). No cross-lang splits — mlx-tune sees each lang as its own SFT job (§3.3 in `W6_QLORA_SPEC.md`).

| Lang | Train (80%) | Val (10%) | Test (10%) | Total |
|---|---|---|---|---|
| kok | 80 | 10 | 10 | 100 |
| pa  | 80 | 10 | 10 | 100 |
| **TOTAL** | **160** | **20** | **20** | **200** |

**Seed:** `SEED = 20260926` (matches `build_manifest.py:166`, the W3 probe seed — keeps reseeds deterministic across probe22 ↔ W6).

**Split method:** deterministic by `hash(image_id) % 10`:
- `bucket = (hash(image_id) & 0x7FFFFFFF) % 10`
- bucket in `{0,1,2,3,4,5,6,7}` → train (80/100)
- bucket in `{8}` → val (10/100)
- bucket in `{9}` → test (10/100)

Stratification check: per-language counts must sum to 80/10/10 within ±1; if any lang falls outside, swap boundary items between train/test until balanced. Document the swap list in the build script's run log.

### 2.1 Why this split is honest-empty-correct

- **No test set in SFT/RLVR.** §6 hard rule from `AGENT_PROTOCOL.md`. mlx-tune's built-in eval (`mlx-tune eval`) MUST be run on the val split (20 items) — the test split (20 items) is held out for the final McNemar gate in `QLORA_EVAL_SPEC.md`.
- **No leakage between train and val/test** — guaranteed by per-image_id bucketing (image_id is the unique key).
- **No barred-lang data** — only `language in ('kok','pa')`.

## 4. Build script spec (one-time, before any QLoRA training)

`build_sft.py` (new file at `level2/probe22/build_sft.py`):

```
inputs:
  --manifest level2/probe22/manifest.json
  --image-meta level2/probe22/image_meta.json
  --image-root /Users/srujansai/Desktop/South/level2/probe22/images
  --out-dir level2/probe22/w6_data
  --langs kok,pa
  --seed 20260926
  --max-text-chars 1024   # cap absurdly long GT (kok max 4011, pa max 2409)

steps:
  1. Load manifest + image_meta.
  2. Filter: language in langs AND gt_source == 'official_pdf_layer'.
  3. Build image_path = {image_root}/{language}/{image_id}.png.
  4. Verify image_path exists; skip + log if missing (don't crash).
  5. Apply §6.5 control-char strip (MAX_CTRL_CHARS=3) on gt.
  6. Compute split bucket = (hash(image_id) & 0x7FFFFFFF) % 10.
  7. Write per-lang jsonl (full + train + val + test).
  8. Print summary: total / per-lang / per-split counts.

exit codes:
  0 = success, summary printed
  2 = missing image file (skipped)
  3 = control-char strip dropped GT to empty (skipped + logged)
```

### 4.1 Verification (must run after build)

```bash

# 2. Schema check (jq required)

    echo "=== $f ==="
    head -1 $f | jq -r 'keys | join(",")'  # image_id,image_path,gt,lang,split,source_pdf,...
done

# 3. Image existence
for f in level2/probe22/w6_data/{kok,pa}_sft.jsonl; do
    while IFS= read -r line; do
        echo "$line" | jq -r .image_path
    done < $f | xargs -I{} test -f {} || echo "MISSING"
done
```

All counts must match: total=200, kok=100, pa=100, per-lang train=80/val=10/test=10. All image_path must exist.

## 7. Risks / honest-empty register

- **GT control-char residue.** Manifest was already purged at `MAX_CTRL_CHARS=3` (level2/probe22/extract_gt.py). All 200 rows pass the gate today; build_sft.py re-verifies before writing.
- **Image_meta coverage 90/100 for pa.** 10 pa items lack image_meta.json entries. SFT does not need width/height — non-blocking. Logged as honest-empty in the build summary.
- **Long GT (>1024 chars).** 100% of pa rows and ~95% of kok rows are under 2400 chars. We cap at 1024 chars to keep mlx-tune seq-len tractable on M2 Max 32GB. **Truncation risk:** a single line that exceeds 1024 chars may be cut. If truncation matters, use `--max-seq-len 2048` instead (doubles memory; smoke test must verify).
- **No diversity check.** All 100 kok items come from 2 PDFs; all 100 pa items come from 2 PDFs. QLoRA could memorize styles; the held-out test split (20 items, same 2 PDFs but different pages) catches this. If test CER ≪ val CER → overfit, kill adapter (K1 fires).
