## 0. Purpose

The 5-item smoke test is the **first-run MLX sanity check** that gates the real QLoRA training run on `kok` + `pa`. It validates:

1. mlx + mlx-vlm + mlx-tune imports succeed end-to-end (K4(a) gate already passed at W5 freeze).
2. The exact training command (recipe) from `W6_QLORA_SPEC.md` §2 produces a real adapter on M2 Max without runtime errors.
3. CER/WER metrics emit on the held-out 5-item set (proves the eval pipeline works).
4. Memory peak stays within K4(b) budget (≥ 4 GB reclaimable + headroom).
5. Wall-clock is ≤ 2× the expected per-iter cost (otherwise abort to wrap-only).

If ANY of the 5 fail → abort the full run, ship wrap-only (D1 stage-1 is the guaranteed deliverable per `LEVEL7_RESEARCH_CAMPAIGN.md` §11).

## 2. Smoke-test SFT recipe (same as real run, smaller batch)

The smoke test uses the **identical** `mlx-tune sft` recipe from `W6_QLORA_SPEC.md` §2.1, with these substitutions:

```bash
# Smoke-test data file (5 items, format same as QLORA_TRAINING_DATA.md §3)
cat > /tmp/w6_smoke_5.jsonl <<EOF
$(python3 -c "
import json
m = json.load(open('level2/probe22/manifest.json'))
items = [i for i in m['items'] if i['image_id'] in ('kok_o009','kok_o042','kok_o088','pa_o018','pa_o003')]
for it in items:
    img_path = f'/Users/srujansai/Desktop/South/level2/probe22/images/{it[\"language\"]}/{it[\"image_id\"]}.png'
    print(json.dumps({'image_id': it['image_id'], 'image_path': img_path, 'gt': it['gt'], 'lang': it['language']}, ensure_ascii=False))
")
EOF

# Smoke-test SFT (3 epochs, batch=1, grad-accum=2 — half of real run for speed)
mlx-tune sft \
    --model mlx-community/Qwen2.5-VL-3B-Instruct-4bit \
    --data /tmp/w6_smoke_5.jsonl \
    --output /tmp/w6_out_smoke_kok_pa \
    --lora-r 16 --lora-alpha 32 --lora-dropout 0.05 \
    --batch-size 1 --grad-accum 2 \
    --grad-checkpoint \
    --lr 1e-4 --epochs 3 \
    --max-seq-len 1024 --image-res 512 \
    --metrics cer,wer \
    --seed 20260926
```

**Recipe delta vs real run:** grad-accum 2 (vs 8 in production) and 3 epochs (vs 3 in production). The goal is speed (≤10 min), not fidelity.

## 5. Pass / fail criteria (binary verdict)

| Criterion | Pass | Fail (→ abort QLoRA, ship wrap-only) |
|---|---|---|
| mlx imports succeed | `import mlx; import mlx_vlm; import mlx_tune` returns 0 | ModuleNotFoundError, ImportError, or any other exception |
| SFT command exits 0 | exit code 0 within ≤10 min | exit ≠ 0 OR wall > 10 min (R6 trigger) |
| Adapter file created | `/tmp/w6_out_smoke_kok_pa/adapter.safetensors` exists, > 1 MB | missing OR < 1 MB |
| Adapter loads for inference | `mlx_vlm.generate --adapter ...` succeeds | crash on load OR generation |
| CER/WER metrics emit | `/tmp/w6_smoke_eval.json` has at least one row with CER > 0 | all CER=0 (suggests broken metric) |
| Peak memory ≤ 12 GB | `ps` RSS ≤ 12 GB during run | RSS > 12 GB (K4(b) fires) |

**5 of 6 pass** → proceed to full 100-item run per `W6_QLORA_SPEC.md`.

**3+ fail** → abort QLoRA. Ship wrap-only (D1 default deliverable). Log root cause + smoke-test output to `level2/probe22/w6_eval/smoke_test_verdict.json` for the W5 freeze record.

**1-2 fail** → Verdict reviews before re-attempting. Max 2 re-attempts per `LEVEL7_RESEARCH_CAMPAIGN.md` §1 fix-loop law, then escalate.
